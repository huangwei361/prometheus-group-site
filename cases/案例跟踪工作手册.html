﻿# 长期健康案例跟踪工作手册

版本 v1.0 ｜ 生效日期 2026-11-18 ｜ 适用对象：菲玛科技 AI 平台组、维塔生命临床前组、瑞吉再生类器官组 制定：普罗米修斯集团总部（枢）

0. 这份手册是干什么的（一句话）

把每个案例从"看过一次"变成"一直在盯"，并且盯出来的数据能直接喂给 AI 系统、支撑产品决策。

不是写病历，是建一条会长大、能查、能交差的数据线。

1. 为什么要有这套东西（背景，通俗版）

现在的状况很典型：一个病人看了一次医生，拿到一张化验单，写了个病历，然后就断了。

三个月后病人说"最近有点不舒服"，医生问"上次指标是多少？"——查不到。

我们要解决的正是这个断点：

老办法新办法
一次性问诊，看完就散建档 → 定期回填 → 长期趋势
只有化验单，没有时间轴基线 / 当前 / 目标 / 趋势 四栏对照
靠记忆判断"是不是变差了"用数字看趋势，看连续 3 次而不是看 1 次
经验躺在某个医生脑子里变成结构化数据，能训练 AI，能沉淀成产品

一句话：病人是"数据源"，数据是"产品原料"。我们要做的是把原料标准化地采上来。

2. 一个案例由哪几块组成（固定结构）

每个案例必须包含这 8 块，缺一块就是没建档完成：

  1. 病例档案（core）— 编号、年龄段、性别、主诊断、病程、当前用药、核心问题
  2. 诊断盲点清单（core）— 这个病"最容易被漏掉的前提"有哪些，各 5–10 条
  3. 跟踪指标体系（m1 + m2）— 分 4–6 组，每项含基线/当前/目标/频次/趋势
  4. 治疗与干预阶梯（path）— 阶段 0 到 N，每阶段写清"做什么、什么时候触发、谁负责"
  5. 病程时间轴（path）— 关键节点，带日期
  6. 随访节奏表（path）— 什么项目、多久一次、为什么
  7. AI 分工表（path）— AI 在这个案例里具体干哪几件事
  8. 免责声明（core）— 固定话术，见第 6 节

文件对应关系（务必记住）：

data/c0xx-core.json   → 块 1、2、8
data/c0xx-m1.json     → 块 3 的前半（核心指标）
data/c0xx-m2.json     → 块 3 的后半（副作用/共病/风险）
data/c0xx-path.json   → 块 4、5、6、7

构建后生成 data/c0xx.js，页面 <script> 引入它渲染。不要手改 .js，只改 .json。

3. 日常操作流程（三条线并行）

线 A：每周数据回填（菲玛科技主责）

第一步：拿到新数据（复查报告、化验单、就诊记录、用药变化、副作用反馈）

第二步：写进 JSON——只改对应指标的 current 和 trend 两个字段，不要动 target（目标值是医师定的，不是我们定的）。

第三步：跑构建

powershell -NoProfile -ExecutionPolicy Bypass -File group\cases\build.ps1

第四步：核对输出，必须看到类似：

c001.js written, groups=5, metrics=8+5+4+10+5
c002.js written, groups=5, metrics=6+6+6+5+3

组数或指标数不对 → 说明 JSON 写坏了，立刻回查。

第五步：浏览器打开 group\cases\index.html，切到对应 Tab，肉眼确认表格出数。

线 B：每周方案复核（主诊医师 + 菲玛 AI 组）

每 7 天做一次，只看三件事：

  1. 有没有新的诊断盲点需要补查（盲点清单里还有多少条是"待执行"）
  2. 指标有没有越过安全线（超标 / 恶化 / 反弹）
  3. 治疗阶梯该往下走还是该停一停

产出：一页纸的周报，格式见第 5 节。

线 C：每月产品化沉淀（菲玛 + 维塔 + 瑞吉）

每月一次，把案例里积累的东西抽出来：

  • 菲玛：哪类预测规则在真实数据上准 / 不准（→ 改进 AI 模型）
  • 维塔：哪些副作用是被忽略的市场缺口（→ 抗衰 / 抗炎产品立项依据）
  • 瑞吉：哪些结构与功能指标适合做类器官筛选终点（→ 研发管线依据）

4. 指标填写规范（最容易出错的地方）

4.1 五种取值，用词统一

写法含义什么时候用
待测该查了，但还没查开了检查单，结果没回来
待填还没安排 / 拿不到患者暂时不做这项
待确认有信息但不确定药名、剂量、日期记不清
待算需要计算得出例如心血管 10 年风险分
具体数字已有结果填数值 + 单位

⚠️ 禁止留空字符串。空字符串会让页面上出现空白格，看不出是"没做"还是"忘了填"。

4.2 trend 只允许三个值

  • "up" 上升 —— 指标在变差（注意：体重上升是好事，指标方向要按"是否接近目标"判断，不是看绝对方向）
  • "down" 下降
  • "flat" 持平

4.3 star: true 是"关键指标"

只有满足这两条之一才打星：

  1. 这个指标决定方案走向（比如 C-001 的 IgG 决定能不能减激素）
  2. 这个指标是产品的核心卖点（比如 C-002 的"实际服药天数占比"直接证明依从性管理的产品价值）

全案例星标指标控制在 8 个以内，否则等于没标。

4.4 目标值怎么写

写"临床公认的目标"，不要写"理想值"。例：

  • ✅ "< 2.6（高危<1.8，极高危<1.4）" —— 有分层，可执行
  • ❌ "越低越好" —— 不可执行，医师没法判断达标没达标

6. 三条红线（谁都不能碰）

红线一：去标识化

公开版案例绝对不能出现：

  • ❌ 姓名、住院号、门诊号、身份证号、手机号、住址
  • ❌ 具体医院名称、科室全称、医生姓名
  • ❌ 原始影像图、原始化验单照片（可识别）
  • ❌ 精确到具体日期的病历节点（"2026-03-15 入院"这种要改成"约 1 年前"）

✅ 允许的粒度：编号、年龄段、性别、粗略病程、疾病大类。

如果董事长明确书面同意公开可识别信息，需另行记录授权范围（授权人、授权范围、有效期），存 group/cases/ 下单独文件。

红线二：AI 不开处方

所有 AI 输出、所有模板、所有周报，必须带这句：

本内容用于健康管理方法展示与研究分析，不构成医疗建议，所有诊疗决策由主治医师负责。

不许出现："建议加量""建议停药""可以停激素了"这类祈使句。 只允许出现："若 X 指标持续 > Y，则可与医师讨论 Z 方案"。

红线三：数据来源可追溯

每一个填进 current 的数字，必须能说清楚是哪天、哪个来源（哪次复查/哪份化验单/谁口述）。 说不出来源的数字不许填。

冲突回避：菲玛负责"判断"，维塔负责"研发产品"。涉及自家产品的指标，不得由维塔单独定义或单独解读结论。

8. 新增一个案例（完整流程，组长照做即可）

第 1 步：复制模板

group\cases\data\c001-core.json   →  c0xx-core.json
group\cases\data\c001-m1.json     →  c0xx-m1.json
group\cases\data\c001-m2.json     →  c0xx-m2.json
group\cases\data\c001-path.json   →  c0xx-path.json

第 2 步：改内容

  • core：id / code / title / subtitle / updated / owner / support / tags / profile / summary / disclaimer / diagnostic_gaps
  • m1 / m2：metric_groups 数组，每个组 {name, note, metrics:[...]}
  • path：pathway / timeline / followup / ai_role / notes

第 3 步：注册

  1. group\cases\build.ps1 → $ids = @('c001','c002') 加上新 id
  2. group\cases\app.js → var ORDER = ['c001','c002'] 加上新 id

第 4 步：构建 + 验证

powershell -NoProfile -ExecutionPolicy Bypass -File group\cases\build.ps1

看到 c0xx.js written, groups=X, metrics=... 即成功。

第 5 步：浏览器打开 group\cases\index.html，确认新 Tab 出现、指标表有数。

9. 常见故障与排查

现象原因怎么办
页面表格空白没跑 build.ps1，或改了 JSON 没构建重跑构建，刷新页面（Ctrl+F5）
页面出现"暂无数据"app.js 的 ORDER 里没加 id补上 id
构建报 JSON 解析错误JSON 里有中文全角符号、尾逗号、或括号不配对逐个文件检查；建议用 VSCode 的 JSON 格式化验证
指标组多出一个空组core 里没有 metric_groups 字段不用管（构建脚本已过滤）；若出现说明脚本被改过
浏览器改了没生效缓存Ctrl+F5 强制刷新
想删临时文件工具会拦截删除命令单独提一次删除请求让人工批准

10. 附录：现有案例速查

编号主题主责协作状态
C-001自身免疫性肝病（激素减量与长期安全管理）菲玛科技维塔生命、瑞吉再生跟踪中
C-002高血脂长期跟踪与控制菲玛科技维塔生命跟踪中

C-001 当前最该补的三项（阻塞方案推进）：

  1. 免疫球蛋白 G（IgG）—— 不达标就不能减激素
  2. 肝脏硬度（FibroScan）+ 血小板 —— 决定纤维化分期与再生治疗介入时机
  3. 骨密度 T 值 —— 老年人长期用激素的账，必须有基线

C-002 当前最该补的三项：

  1. 实际服药天数占比 —— 依从性是达标率的直接解释变量
  2. 10 年心血管风险分 —— 决定目标 LDL 定在哪
  3. 脂蛋白(a)（Lp(a)）—— 一次性检测，终生不变，漏了就永远不知道
